# Agent and sandbox compatibility research

Checked 2026-10-22 against each candidate's official repository, documentation and/or package feed. This report describes upstream capability, not installation in this Android project. None of the candidates below was installed or smoke-tested on the Samsung Galaxy M10 or in the sandbox. The target remains Android API 28, ARM32, package `com.usmanandumar.app`.

## OpenHands

**Identity and release.** The exact project is [OpenHands/OpenHands](https://github.com/OpenHands/OpenHands), not its separate SDK or sandbox-server repositories. Stable release `v1.30.1` was published 2026-10-22. OpenHands/OpenHands and its SDK are MIT-licensed; individual ecosystem repositories, images, extensions and dependencies need separate license review. [Official releases](https://github.com/OpenHands/OpenHands/releases) · [license](https://github.com/OpenHands/OpenHands/blob/main/LICENSE).

**Runtime and fit.** Agent Canvas is a Node/TypeScript browser client requiring Node 24+ and uv/uvx; the SDK/server use Python 3.12+ and uv. Local sandbox execution depends on Docker; documented host environments are desktop/server OSes, not Android API 28/ARM32. Android/Termux compatibility is not established. Remote Agent Server, Cloud and Enterprise backends are documented, but that would be remote execution, not a local phone sandbox. Model credentials and reachable service endpoints are required. [Setup](https://docs.openhands.dev/openhands/usage/agent-canvas/setup) · [architecture](https://docs.openhands.dev/openhands/usage/agent-canvas/architecture) · [backends](https://docs.openhands.dev/openhands/usage/agent-canvas/backends).

**Capabilities and safety.** Upstream documents planning/task tracking, file and command tools, GitHub integration, tests, MCP/plugins, persistence, pause/resume and remote workspace APIs. Agent Canvas itself is not an isolation boundary. A local process uses host permissions; Docker/Kubernetes/remote execution depends on deployment configuration. It should not be enabled on this Android target without a supported remote-service design, authorization model and separate smoke tests. [SDK](https://docs.openhands.dev/sdk/getting-started) · [persistence](https://docs.openhands.dev/sdk/guides/convo-persistence) · [server](https://docs.openhands.dev/sdk/arch/agent-server).

[Docs](https://docs.theopenbuilder.com/) · [release listing](https://github.com/TheOpenBuilder?tab=releases) · [repositories](https://github.com/TheOpenBuilder?tab=repositories).

**Runtime and fit.** The official quick start says no local installation is required; the service runs in a browser. Its FAQ names current desktop browsers but does not document Android API 28, Galaxy M10, ARM32, a native package, or local Termux/PRoot use. It offers a hosted builder workflow and documented Supabase/API connections, not an Android sandbox. Source provenance, release, redistribution rights, resource limits and isolation guarantees were not verified. [Quick start](https://docs.theopenbuilder.com/get-started/quick-start.md) · [FAQ](https://docs.theopenbuilder.com/troubleshoot/faqs.md) · [security](https://docs.theopenbuilder.com/best-practices/security.md).

**Capabilities and safety.** Planning, code edits, preview/debugging, lint/build checks, checkpoints/revert and deployment are documented in the hosted product. Generic shell/GitHub APIs and secure sandbox guarantees are not documented. No Android integration is proposed; catalog it only as an external hosted web service if the user later authorizes that direction.

## OpenManus

**Identity and release.** The maintained upstream is [FoundationAgents/OpenManus](https://github.com/FoundationAgents/OpenManus); the previous `mannaandpoem/OpenManus` repository says it moved. Stable `v0.3.0` was published 2025-04-10. The repository is MIT-licensed; installed dependencies have separate licenses. [Releases](https://github.com/FoundationAgents/OpenManus/releases) · [license](https://raw.githubusercontent.com/FoundationAgents/OpenManus/main/LICENSE).

**Runtime and fit.** The project is a Python 3.12+ agent framework with conda/uv installation and a large Python dependency set. Its local sandbox uses Docker; the repository also documents an optional remote Daytona adapter requiring an account/API key. No E2B integration or Android/ARM32 build is verified. PRoot is not a Docker daemon, so installing packages in ordinary Termux would not reproduce the upstream sandbox boundary. No local install or test was performed. [README](https://github.com/FoundationAgents/OpenManus) · [requirements](https://raw.githubusercontent.com/FoundationAgents/OpenManus/main/requirements.txt) · [Daytona adapter](https://github.com/FoundationAgents/OpenManus/blob/main/app/daytona/README.md).

**Capabilities and safety.** Upstream has planning/task steps, local file and Python tools, browser/MCP integration, optional Docker/Daytona execution and an MIT license. It does not document durable pause/resume/cancel guarantees or a native Android integration. The default non-Docker path can access the host filesystem and Python `exec` is not a security boundary. Daytona is a separate remote service with its own credentials, billing and terms; neither Daytona nor E2B is an Android-local sandbox.

## OpenSwarm

**Identity and release.** The verifiable agent project is [VRSEN/OpenSwarm](https://github.com/VRSEN/OpenSwarm), package `@vrsen/openswarm`, not the separate proprietary `openswarm-ai/openswarm` desktop project. VRSEN's latest stable release is `v1.1.3` (2026-07-18), MIT-licensed. Its exact association with this app ID is not verifiable. [Release](https://github.com/VRSEN/OpenSwarm/releases/tag/v1.1.3) · [license](https://github.com/VRSEN/OpenSwarm/blob/main/LICENSE).

**Runtime and fit.** It requires Node 20+ and Python 3.12+, plus browser, document and media dependencies. The official release assets include Linux ARM64 and desktop targets, but not Android or Linux ARM32. Docker is an optional local deployment and the system is otherwise a terminal/TUI plus FastAPI service. No Android, Termux/PRoot or remote Daytona/E2B support was verified. No install/smoke test was run. [package metadata](https://raw.githubusercontent.com/VRSEN/OpenSwarm/main/package.json) · [Python metadata](https://raw.githubusercontent.com/VRSEN/OpenSwarm/main/pyproject.toml) · [Docker setup](https://raw.githubusercontent.com/VRSEN/OpenSwarm/main/docker-compose.yml).

**Capabilities and safety.** The upstream documents orchestrator and specialist agents, shell and file tools, model-provider integrations, Composio tools, a smoke harness and optional local Docker/FastAPI setup. Pause/cancel/recovery guarantees and server authentication are not established. Tools access host files and persistent shell; Docker mounts host directories. Do not describe it as an Android security sandbox or claim safe operation without a hardened host and per-tool review.

## OpenAI Codex CLI

**Identity and release.** Official upstream is [openai/codex](https://github.com/openai/codex). Stable CLI `0.163.0` (`rust-v0.163.0`) was released 2026-10-15; the newer `0.164.0-alpha.12` is a prerelease. The project is Apache-2.0-licensed, subject to its license notices and third-party dependencies. [Stable release](https://github.com/openai/codex/releases/tag/rust-v0.163.0) · [license](https://raw.githubusercontent.com/openai/codex/main/LICENSE).

**Runtime and fit.** Codex CLI is a Rust/terminal agent. The published launcher requires Node 16+, while the source workspace documents Node 22+, pnpm 10.34.5+ and Rust toolchain requirements. The official supported operating systems are macOS, Ubuntu/Debian and Windows via WSL2. Published native packages list x64 and ARM64 but not ARM32; Android API 28/Termux is not supported by the reviewed docs. Codex Cloud is a separate remote option, not evidence that the CLI runs locally on this phone. [Install requirements](https://github.com/openai/codex/blob/main/docs/install.md) · [npm package metadata](https://registry.npmjs.org/@openai%2fcodex/0.163.0) · [cloud environments](https://developers.openai.com/codex/environments/cloud-environments).

**Capabilities and safety.** Official docs describe repository planning/editing, command execution, tests, GitHub integration, JSONL automation, session resume and approval controls. Local mode uses OS sandboxing and default workspace/network restrictions on supported hosts, but permissions can be widened; local credentials may be stored in `~/.codex/auth.json`. Providers require ChatGPT login/API key or a configured local/compatible endpoint. No ARM32 Android install or test was performed. [CLI](https://developers.openai.com/codex/cli) · [security](https://developers.openai.com/codex/agent-approvals-security) · [sandboxing](https://developers.openai.com/codex/sandboxing) · [authentication](https://developers.openai.com/codex/auth).

## Gemini CLI

**Identity and release.** Official upstream is [google-gemini/gemini-cli](https://github.com/google-gemini/gemini-cli), npm package `@google/gemini-cli`. Latest stable verified release is `v0.65.0` (2026-10-20); the newer preview/nightly feeds are not stable releases. License is Apache-2.0. [Release](https://github.com/google-gemini/gemini-cli/releases/tag/v0.65.0) · [license](https://github.com/google-gemini/gemini-cli/blob/main/LICENSE).

**Runtime and fit.** It requires Node 20+, a shell and internet; official OS documentation lists desktop/server systems. The stable npm package lists native PTY variants for desktop x64/ARM64, not Linux ARM32. No Android API 28 or Termux support is documented. Its optional sandbox requires Docker or Podman and a running daemon, not provided by PRoot. It uses Google login, Gemini API key or Vertex AI/Google Cloud configuration. [Installation](https://geminicli.com/docs/get-started/installation/) · [authentication](https://geminicli.com/docs/get-started/authentication/) · [package feed](https://registry.npmjs.org/@google/gemini-cli).

**Capabilities and safety.** Official sources document plan mode, file and shell tools, testing, GitHub workflows, JSON headless mode, MCP/extensions, session restore/rewind and approval policies. Docker/Podman can isolate tools on a supported host, but command execution remains powerful and policy/confirmation is not itself isolation. No on-device installation, health or smoke test was performed. [tools](https://geminicli.com/docs/reference/tools/) · [commands](https://geminicli.com/docs/reference/commands/) · [sandbox](https://geminicli.com/docs/cli/sandbox/) · [policy engine](https://geminicli.com/docs/reference/policy-engine/).

## Hermes Agent

**Identity and release.** Official upstream is [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent), a self-hosted agent/orchestrator rather than a sandbox service. Latest stable tagged release checked is `v0.22.4` (2026-10-21), MIT-licensed. Source `pyproject.toml` still reports `0.0.0`; use the release tag for the user-facing release reference. [Releases](https://github.com/NousResearch/hermes-agent/releases) · [license](https://raw.githubusercontent.com/NousResearch/hermes-agent/main/LICENSE).

**Runtime and target fit.** Current official installation documentation specifies Python 3.14 and a managed uv/PM setup; Android Termux packages target API 24 `arm64-v8a`/aarch64 only. The platform guide explicitly excludes non-aarch64 Android; the Termux page currently warns its package is broken and a fix is in progress. That does not support the user's ARM32 Galaxy M10/API 28 target. No install or smoke test was attempted. [Termux](https://hermes-agent.nousresearch.com/docs/getting-started/termux) · [platform support](https://hermes-agent.nousresearch.com/docs/getting-started/platform-support) · [installation](https://hermes-agent.nousresearch.com/docs/getting-started/installation).

**Backends and requirements.** Official terminal backends include local, Docker, SSH, Singularity, Modal, Daytona and Vercel Sandbox. Daytona is remote and requires its own account/API key or JWT and organization configuration. E2B is not an official Hermes backend in the reviewed docs; it would require a separate custom adapter/plugin. A configured model provider, credentials and network are required (unless a reachable local model endpoint is used). Pricing/terms belong to the provider, not Hermes. [Tool backends](https://hermes-agent.nousresearch.com/docs/user-guide/features/tools) · [providers](https://hermes-agent.nousresearch.com/docs/integrations/providers) · [Daytona](https://www.daytona.io/docs/en/sandboxes/).

**Capabilities and safety.** Official docs describe planning/todos, file tools, terminal/background processes, GitHub via `gh` skill/MCP, tests, plugins/MCP, SQLite-backed sessions/memory, resume, stop/interrupt and optional checkpoints. The default local terminal is not a security sandbox; Docker backends can harden execution, but session environment variables are exposed to commands and plugins run in-process by default. Android background execution is not guaranteed. Do not catalog as ARM32-compatible or as installed/verified. [Security](https://hermes-agent.nousresearch.com/docs/user-guide/security) · [plugins](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins) · [checkpoints](https://hermes-agent.nousresearch.com/docs/user-guide/checkpoints-and-rollback).
